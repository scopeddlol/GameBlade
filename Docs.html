GameBlade

Current deployment and operator guide for version 0.8.

Architecture

GameBlade can run on one machine or as a Coordinator with one or more Nodes. A public reverse proxy may expose the Coordinator. Nodes never need an inbound game-transfer port.

Desktop
parallel HTTPS ranges
Coordinator
authorizes, verifies, streams
Node
outbound authenticated HTTPS

For each Desktop byte range, the Coordinator selects a Node known to hold the game and queues a 10 MiB ZIP chunk request. The Node reads and verifies the chunk, posts it to the Coordinator, and the Coordinator verifies it again before streaming it to Desktop.

Every install is one ZIP64 package. The Desktop keeps several ranges in flight, writes chunks at their offsets, records resume journals, verifies hashes as bytes arrive, and automatically unpacks the completed package with a bounded parallel worker pool.

One-machine quick start

git clone https://github.com/scopeddlol/GameBlade.git
cd GameBlade
cp .env.example .env
# Set LIBRARY_PATH in .env
docker compose up -d

Open http://<host>:8080, create the first administrator, and let the read-only library scan.

Images and roles

Image Purpose
gameblade Standalone API, UI, database, scanner, and local files.
gameblade-coordinator Public API, database, catalog coordination, and HTTPS download streaming.
gameblade-node Scans mounted libraries and supplies chunks through outbound HTTPS.

Coordinator and reverse proxy

Start with docker-compose.coordinator.yml. Caddy, Pangolin, Cloudflare Tunnel, or another HTTPS reverse proxy can publish port 8080 normally. Set TRUST_PROXY=true and keep SECURE_COOKIES=auto. WebSocket forwarding is needed for live social features.

No extra UDP service is part of downloads. The public proxy carries Coordinator HTTPS, including download responses and Node long polls.

Set up a Node

  1. Copy docker-compose.node.yml to the machine holding the games and update its read-only volume.
  2. Run docker compose up -d.
  3. Create a code in Admin → Nodes → Enrolment.
  4. Open the Node's local page on port 8080 and enter the Coordinator HTTPS URL and code.

The code is spent after registration. Unused codes can be deleted. Nodes can be renamed inline from Fleet. Nodes store identity in /data/node-state.json; back that file up.

The local Node control center has three workspaces. Overview shows mounts, reporting, scan progress, and hashing progress. Game intake is a file-browser view of every top-level folder and supported archive: approve an entry to record an explicit decision, ignore it to withdraw it from the Coordinator and future scans, or reset it to automatic behavior. These actions never alter the read-only game disk.

Backups keeps complete Coordinator recovery archives on the Node. A copy includes SQLite, settings and config state, every cloud-save version, uploaded media, the published client, and cached artwork. Use Back up now to force a new one; otherwise the Node keeps a fresh daily copy automatically and retains the newest seven in /data/coordinator-backups. Size the Node's writable /data mount accordingly. Game packages are not duplicated inside these archives because the Nodes already hold them.

volumes:

Admin operations

  • Fleet: state, coverage, transfer totals, rename, library assignment, block, and remove.
  • Analytics: total Coordinator delivery, Node-backed share, coverage, busiest Nodes, and popular games.
  • Enrolment: create and delete unused one-time codes.
  • Catalog: the “Games with no Node” tile opens the affected games for removal.

Desktop connection cards show friendly Node names only. They never display Node, client, or Coordinator addresses, hostnames, domains, or ports.

Download behavior

  • One ZIP64 package per game, cut into fixed 10 MiB chunks with up to eight concurrent HTTPS requests by default.
  • Resume journals survive restarts; transient failures retry with backoff.
  • Chunk SHA-256 is checked at Node, Coordinator, and Desktop. A package is never offered until every 10 MiB chunk has a hash on the current grid.
  • Quotas and speed limits are enforced once at Coordinator, without double-counting Node source records.
  • If one Node fails, Coordinator tries another current holder before returning unavailable.

Troubleshooting

Node is not Active Confirm outbound HTTPS to the exact Coordinator URL. Check the Node page and container logs. No inbound Node port is required.
File is no longer available Confirm the game is in an online Node catalog and every file is fully chunk-hashed.
Node backup failed Confirm the Node is enrolled, can reach the exact Coordinator URL, and has enough free space in its writable /data mount. The Backups workspace retains the last error and can force a retry.
Catalog is too large Use current Node and Coordinator images. Catalogs upload in bounded batches and catalog routes accept large reports.
Download is slow Check Node disk, Node uplink, Coordinator egress, configured limits, and Desktop concurrency.
